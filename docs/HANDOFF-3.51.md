# 经纬纪 3.51：让详图自动出现，并优先加载历史边界

日期：2026-11-12。承接3.50，针对用户报告的“放大仍然只有粗图、详图等待过久”完成本批改进。发布和GitHub的确切结果见 `verification-3.51/publication.json`。

## 已完成

1. 修正自动模式的覆盖率门槛。以前即使当地有数十条真实详图，只要它们没有覆盖80%的视野，全部细边界都会被隐藏。现在已有的、符合所选年代的区域详图自动出现。覆盖不足时保留12%透明度的全球概览底色，同时关闭概览边界线，避免把两份不同轮廓叠成双线；提示为“局部详图 · …条 · 概览底色”。用户仍可切回概览或明确选择地区来源。没有记录时恢复概览。
2. 提前一级缩放预取对应年份、对应窗口的本地详图；直接打开地区链接时，在地图初始化期间开始请求。全球默认视图、关闭边界、现代参照和手动概览模式不启用这项预取。
3. 本地详图优先于在线补充；等待上限4秒，之后在线来源可独立开始。城市大索引、细海岸、湖泊分片等可选数据给历史边界最多4秒的优先窗口，失败或停滞不会无限阻塞其余地图。两张对照地图的请求可以独立结束。
4. 为1492、1500年中欧详图增加整数差分传输包。全部189条记录的坐标逐项恢复后与原始文件严格相等，没有删顶点、少画小岛、改年代或改变属性。下载体积分别从1,118,302降到690,928字节、1,639,961降到1,005,009字节。原始文件和研究来源保持不变；传输包损坏会回退到原文件。
5. 详图记录列表延迟读取瓦片坐标，只有计算标注时才展开几何。详图已显示时，缩放不再重复加工被隐藏的整张世界概览。放大后的概览线减细、降低对比度；细图采用较柔和的墨色，与地形和水系协调。

## 浏览器实测

同一台Chrome，1512×900视口（地图1512×672），1492年、中心[7.6,48.2]、zoom6.5；4Mbit/s下载、80ms延迟、禁HTTP缓存。为避免第三方瓦片波动，受控对照屏蔽外部HTTPS，两版均使用本地固化资料。基线固定为3.50源码提交82b61fde，新版是本批候选。三组交替测量，测量期间没有运行完整验证进程。

| 观测 | 3.50 | 3.51 |
| --- | ---: | ---: |
| 地区记录达到可绘制状态，中位数 | 13,430.1ms | 7,847.1ms |
| 自动显示这些详图 | 否，停在partial | 是 |
| 过渡概览达到可绘制状态，中位数 | 4,036.3ms | 4,745.7ms |

详图就绪约提前41.6%；直接打开地区链接时过渡概览晚约709ms，这是请求优先级的取舍。这个结果不代表公网所有地点、所有年份，也不是与竞品的同条件速度胜负。就绪以地图的源完成与后续渲染查询为准，不是下载结束或所有外部图层完全空闲；新版首帧59条，稳定后61条，与基线稳定后的ID集合、视口和相机一致。原始数据见 `verification-3.51/browser/measurements.json`。

原生浏览器交互还确认：5.6→6.6放大自动进入详图，缩小回5.6恢复概览；1500年的地图和详图均切至1500，未继续显示1492年的边界；最终1492、zoom7.2自动模式显示43条当前视野记录。最终截图见 `verification-3.51/browser/regional-detail.jpg`。本地应用未报告新的控制台错误，看到的错误来自已有Zotero浏览器扩展。

## 对照与未采用的尝试

本次实际打开 [Chronosphere](https://worldbyyear.com/) 和 [Phersu Atlas 1850年视图](https://www.phersu-atlas.com/tile-maps/classic/detail_group/1850/1/1/view/mercator)。前者将地球、细轮廓和时间轴作为视觉重点，后者让政治色块、海岸和水系有清楚层次。本批参考这种层次关系，把粗概览线退出详图视野，保留可读地形；没有复制它们的页面或将其网站宣传当作经过核实的数据覆盖。

曾试验Mapshaper的35米拓扑简化，但1492年样本丢失两个小环，已放弃，未进入产品。也试验过渲染源的0.1简化容差，最终恢复原有0容差。上线内容使用无损传输和优先级优化，不靠减掉细节取得上述结果。地图引擎资料参考：[MapLibre大数据优化](https://maplibre.org/maplibre-gl-js/docs/guides/large-data/)、[源配置](https://maplibre.org/maplibre-style-spec/sources/)。

## 2. 语义与覆盖率的界面文案（实测原文）

- 开关：按钮「暴行记录」，tooltip「独立图层：针对非战斗人员的单方面暴力，与战役层语义不同」。
- 图层说明（`#atrocityNote`，图层面板内，桌面实测可见高度 115 px）：
  > 独立图层：只记录来源所述、针对非战斗人员的单方面暴力，与战役层的两军交战不属同一语义；两层按维基数据实体互斥。本层中文名覆盖有限（37/293），多数条目以其来源语言的名称显示，不作音译或机翻。详情页不判定责任方或性质。
- 详情页首段（每条记录都显示）：
  > 本层为针对非战斗人员的单方面暴力，与战役层的两军交战不属同一语义；两层按维基数据实体互斥。本层不判定责任方或性质，只记录来源所述事件。
- 无中文名记录的详情页回落提示：
  > 该记录没有来源中文名，此处显示其来源语言（英文）的名称；本层不作音译或机器翻译。
- 状态行（`#atrocityStatus`）：关闭时「独立图层 · 默认关闭」，开启时「N 条同期暴行记录」。
- 图例后缀：「· N 条暴行记录」，并在 `zoom<3` 时加「（放大地图后显示）」、在地区详图态加「（地区详图中隐藏）」。
- 来源页统计卡：「293 单方面暴力事件记录」；方法节原文：
  > 针对非战斗人员的单方面暴力另设独立图层，收录 293 条来源记录，与战役层按维基数据实体互斥，绝不混排。其中仅 37 条有来源中文名，其余 256 条以来源语言名称显示，不作音译或机器翻译。本层不判定责任方或性质，只记录来源所述事件；记录来自维基数据实体声明，条目注记标明参考链接的有无。

## 4. 图层可见性规则（如实说明）

该层与战役层共用同一条抑制规则：`zoom<3` 或**地区详图激活**（`regional.detailedActive`）时不绘制标记。

实测：`[125.4,-9] zoom 6`（帝汶一带）在等待 9 s 后 `regionalStatus=ready`、`regionalActive=true` → 标记被抑制为 0；`[80,10] zoom 4.5`（南亚）`detailedActive=false` → 标记正常绘制。也就是说：**本层标记主要出现在 zoom 3–5.5 且该地没有地区详图的视野**，放大到街区级时由既有设计隐藏——图例此时显示「（地区详图中隐藏）」，详情与来源页仍完整可读。这与战役层的行为一致，未做任何放开。

## 6. 仍缺什么

1. **中文名覆盖 37/293 是数据事实**，不是界面缺陷：已在图层说明、来源页、无中文名记录的详情页三处如实呈现；界面不作音译或机翻（与政体目录的回落做法一致）。
2. **未接入搜索**：这是刻意选择——任务禁止把两类记录放进同一个列表，因此没有把暴行加进战役/事件搜索命中。
3. **需要 Lead 盖章**：本轮改了 `public/*.js` 与 `public/style.css`（新增 `public/atrocities.js`），按约定未运行 `prepare:assets`。
4. 测试中「Biak massacre」与同年的「利逵萨教堂大屠杀」坐标几乎重合，会被既有的重叠过滤丢弃；为点开它，我在验证脚本里临时把 `active` 收窄为这一条（**只影响验证过程的候选集合**，标记/点击/详情代码路径未改），已在 JSON 中记录。

## 7. 既有缺陷（本轮发现、未改，建议 Lead 定夺）

`public/style.css` 已提交的内容里有 **15 处字面 `\n`**（反斜杠+n，不是换行）。CSS 解析把 `\n` 当成转义，于是 `.no-territory*` 一组选择器被解析成 `n.no-territory-title`、`n.no-territory-grid`、`n.no-territory-card`（CSSOM 实测），这些规则**不会命中任何元素**，即"无疆域政体"补充卡片的样式当前未生效。修法很简单（把字面 `\n` 换成真实换行），但属于本任务之外的既有内容，且可能有其他成员在处理该区块，故本轮只记录、未改动。

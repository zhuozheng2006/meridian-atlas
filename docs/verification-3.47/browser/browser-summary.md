# 3.47 浏览器验证：同年边界复用

同一年份切换语言时，候选版复用了已完成的边界结果，消除了本次测试中的重复几何处理和地图源提交。结论适用于已经加载完成的当前帧；首次打开地图、切换到边界确实不同的年份仍需要原有计算与提交，不能据此宣称首屏已经提速。

本报告只读取主任务保存的真实 Chrome 测量文件，没有另外操作浏览器。`browser-summary.json` 保留原始精度、各轮调用与事件、文件 SHA-256 和汇总。读取器区分了 CDP 的 `result.value` 包装与直接值两种文件结构，原始文件未修改。

## 同构建、同视图对比

主任务确认 `candidate-language-{1,2,3}.json` 与 `same-build-original-language-{1,2,3}.json` 来自同一构建，其中对照恢复原 displayTerritories 行为。文件本身记录了相同视图，但没有资产版本戳字段；“同构建”来源于测量任务的过程记录。视图为 1492 年，中心经纬度 [25,18]，缩放 1.54，地图尺寸 **1512×543**；顺序均为 en、zh、bi。

| 指标 | 原行为 | 当前帧复用 |
|---|---:|---:|
| displayTerritories，en / zh / bi | 486.2 / 477.6 / 472.2 ms | 0.2 / 0.1 / 0.2 ms |
| displayTerritories 中位数 | 477.6 ms | 约 0.2 ms |
| 每轮 polities.setData | 1 / 1 / 1 次 | 0 / 0 / 0 次 |
| 每轮大型边界 JSON 序列化 | 1 / 1 / 1 次 | 0 / 0 / 0 次 |
| 每次重复序列化字符数 | 18,752,685 | 无重复序列化 |
| 观测窗口长任务次数 | 2 / 2 / 2 次 | 0 / 0 / 0 次 |

原行为三轮分别记录了 505+455、495+409、485+457 ms 的长任务。候选三轮观测窗口中未记录长任务；此结论不能扩大为网站所有交互均无长任务。候选耗时已接近浏览器计时分辨率，因此不采用“快数千倍”的宣传方式。

两组每一轮的 136 个原始要素 ID 及顺序完全一致；观测到的各帧均有 136 个原始要素、11 个标签，年份控件可用，语言按 en、zh、bi 更新。候选各轮地图源保持加载完成；对照每轮重新触发一次地图源加载。

`displayTerritories` 已包含其中同步发生的 setData 和序列化，不能再叠加这些嵌套计时。完整 `setYear` 中位数从 485.9 ms 变为 9.8 ms，仍包括更新标签等其它工作。

采样 `elapsed` 中位数为对照 2229.4 ms、候选 35.2 ms，仅作辅助记录。它包含测量启动、工具触发排队和读取时机；对照最后一帧还可能出现 polities 已加载而 `map.loaded()` 为 false，因此不能把该数值描述为精确的点击到呈现时间、整个地图 idle 时间或首屏加载时间。

## 数据和源生命周期

`baseline-payload.json` 的原始绘制结果包含 137 个要素，其中 136 个为原始疆域要素，JSON 长度为 18,752,685 字符。`style-diff-ownership.json` 验证了同一个 Source 对象被样式差分改成空数据（0 要素）后，重新显示目标帧恢复为 137 要素，恢复后的完整 JSON SHA-256 与原结果相同：

```text
30d0cb79905a87b03a4e4780cac29fd814daa67ab743abedb53833c0d33c9d6f
```

这支持“不会因复用缓存而忽略外部对同一源的改写”以及该实际路径下绘制结果保持一致。该记录显示一个缓存帧、一次派生构建，恢复通过重新提交完成，而非重算边界。

`cshapes-switch.json` 的最终状态为 1945 年、CShapes、country 模式，记录要素数 170，缓存仍仅保留一帧。它证明本次真实浏览器切换进入了对应数据与绘制模式；单个最终状态记录不等同于 CShapes 全年份数据保真验证。

## 早期基线单独保留

`baseline-language-{1,2,3}.json` 来自早期构建，地图尺寸为 **1512×599**。其 displayTerritories 为 485.2 / 465.1 / 468.0 ms，中位数 468.0 ms；每轮均有一次地图源提交和一次 18,752,685 字符序列化。它与上述 1512×543 测量分组保存，未混入同构建对比，也未作为相同视图的基线计算收益。

## 可用于发布说明的措辞

同一年份切换中英文时，地图会复用已完成的边界结果。此次桌面 Chrome 同构建测试中，边界显示处理由约 478 毫秒降至约 0.2 毫秒，并省去了每次约 1875 万字符的重复地图数据序列化和提交；原始要素和绘制结果保持一致。首次打开地图和切换到不同边界年份的加载速度仍需继续优化。

## 下一步全球首帧方向

以下是后续实验建议，本批未实施：

1. 从全新页面导航分别记录原始数据下载、解压、组装、曲线与共边处理、主线程序列化、地图 Worker 建索引/结果回传以及首次可用画面，联合观察长任务与内存峰值。当前同年热路径收益不能代替这些首帧证据。
2. 优先尝试把现有的精确派生算法移入 Worker，并把跨线程传输和结构克隆成本纳入端到端对比。原始数据、选择、下载以及曲线开关仍需维持同样语义。
3. 大型 GeoJSON 的传输及回传优化需要一起验证 getData、serialize/getStyle、setStyle、取消/失败重试和双地图生命周期。证明总链路改善与内存可控后再采用，不能仅凭 Worker 内耗时判断。
4. 默认继续使用体积小的原始数据包。若评估预生成结果或按视野组织数据，应同时比较下载膨胀和精确几何等价，不能通过丢失坐标、边界碎片或改变曲线精度制造性能收益。
5. 后续发布门槛采用同构建、同视图、全新加载的重复测量，并覆盖移动设备或低内存条件。当前报告不作跨设备速度或总内存下降承诺。

## 2. 单一来源之后暴露的两处系统性漂移（第九行下方，Lead 要求）

前置检查改为直接读取闸门脚本的判据常量后，两份副本的差异立刻显形：

| 判据 | 漂移形态 | 具体差异 |
|---|---|---|
| 繁体字表 | **漏字** | 闸门版多 20 余字：爾、軍、戰、勝、歐、亞、羅、蘇、聯、義、紀、興、漢、滿、佔、爭、萬、長、門、開、關、風、飛、書、讀、詞 |
| 评价性措辞表 | **字形式不匹配** | 闸门版用**简体**（伟大、最强、无敌、邪恶、明显落后…），手抄版用繁体/异体，**等于一直在漏判** |

**结论：副本的漂移不是偶发的，是必然的**——手抄副本不是「少了一个字」，而是**在两处系统性出错**（漏字 + 字形式不匹配）。这与「判据取自输出内容」同源：判据只能有一个来源。

## 3. 「机制优于小心」对照表（九行，均有可度量结果）

| 经验 | 反例（小心） | 机制（步骤） | 结果 |
|---|---|---|---|
| 判据来源 | --check 接 tail，退出码来自 tail，FAIL 被当成功 | 按输出内容判定 | 掩盖 FAIL 1 → 0 |
| 写入前自检 | 变量名错误致整批作废 | 写入后立即 JSON.parse | 作废 1 → 0 |
| 字数标准 | 意图标准 45→55 词（无效） | 阈值=闸门 + 清零再装配 | 首次报错 4 → 0 |
| 注记清洗 | 5 次失败，机制化后又犯 2 次 | 装配前固定跑清洗并记录条数 | 手工 4→13→22；机制化后归零 |
| JSON 构造 | 手写大 payload 3 次语法错误 | JSON.stringify 生成 | 语法返工 3 → 0 |
| 校验/改动分离 | 串联修补+装配 | 先 --check 再单独装配 | 返工 2 → 0 |

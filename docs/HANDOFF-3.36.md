## 一、怎么跑起来、怎么验收

```sh
cd world-history-atlas
python3 serve.py --open            # 本机 8767 为项目服务（8766 是另一份原始副本，勿用）
npm run prepare:assets             # 改过 public/*.js|css 后必须先盖章（写 ?v= + 重建 narratives gz）
npm test                           # 全量校验链（长链，末尾必须 EXIT=0）
```

**真实浏览器验证**（无 npm 依赖，CDP + 无头 Chrome）：

```sh
node scripts/verification/browser.mjs            # 驱动库：launch/goto/evaluate/waitFor/screenshot/key/click/clickPoint/dragMap/mapReady
node scripts/verification/audit-geometry-fidelity.mjs   # 源/简化/渲染三段几何保真
node scripts/ohm/verify-ohm-1500.mjs
```

**硬性约定**

| 约定 | 说明 |
|---|---|
| `npm test` 必须全绿 | `stamp-assets --check` 不过就是没盖章 |
| 改 `public/*.js` 才需要盖章 | 只改 `public/data/**` 不需要 |
| 不要抢跑 `prepare:assets` | 它重写全部 `?v=`，会打断正在编辑的人；约定由 Lead 收尾统一盖章 |
| `.gz` 契约 | 所有 `.json.gz` 头 mtime 必须为 0，且与同名 `.json` deepEqual |
| 数据改动后 | 同步刷新 `files.json` / `*-manifest.json` 的 bytes+sha256，否则 `validate-release` 会红 |
| 无头 Chrome 限制 | rAF 被节流到 ~2fps（不报帧率）；SwiftShader 软渲染；阅读器打开时派发可信键盘事件会 SIGABRT |

## 四、必须保留的数据诚实规则（最重要）

这些是用户明确要求、且多次用返工换来的，**不要为了"看起来完整"而放宽**：

1. **不编造、不音译、不机翻**。缺中文名就回落原始语言名并标注（政体 `zhName` 为空回落原名；暴行层 256 条无中文名照此办理）。
2. **"未收录"就写"未收录"**。Cliopatria/OHM 没有的年份或政体，列"未收录"，**绝不借用相邻政体或其它年份的几何**。
3. **区分源精度 / 简化 / 渲染**。1500 中欧轮廓只有 55–102 个顶点，这是**上游数据限制**；政体阅读器直接展示顶点数/边数/中位边长/轴对齐边数。
4. **不猜胜负**。维基数据无稳定 `outcome` 属性 → 战役 `outcome` 全空，原因写进 policy。
5. **类别不能凑**。岛屿/族群/头衔/职位/文明/历史主题/消歧义页**一律不写成政体**（已挡下 90+ 个）；Wikidata 无政体实体者（拉帕努伊）**不建档案**，登记为缺口。
6. **凡数值判据，来自脚本当下的计算**，不做线性外推，不手工摘抄副本。
7. **凡"数据不存在/已见底"的结论**，必须写明查询口径与**核验上限**，并在放宽上限后重跑。

## 五、可复用方法（跨两个大轮验证）

### 十环链（叙述装配）

```
STEPS: parse,lengths,gate,clean,build,override,bindings,apply,gz,verify
```
每批**打印这一行与各环输出**——因为"某一环失败"会报错，而**"某一环缺失"可能恰好通过、完全不显形**（真事：3.35 漏带 `check-bindings`）。

### 两条并列方法

| 场景 | 方法 |
|---|---|
| **撰写侧** | 先定位缺陷落在**哪一栏**，再把那一栏写进起笔规则 |
| **质检侧** | 先定位缺陷在**哪一步**暴露，再把该类别并入**最靠前的那一步** |

### 九行「机制优于小心」对照表（每行都有前后数字）

| 经验 | "小心"的代价 | "步骤"的结果 |
|---|---|---|
| 身份反查 | 凭记忆取 QID 错两次（把贵族家族/人物/Apple 应用当政体）| 99/99、100/100 |
| 核验上限 | "欧洲上限 19 篇"误判，会永久少写 **147 篇** | 上限提到 250 → 候选 700 |
| 注记清洗 | 5 次失败，机制化后作者本人又犯 2 次 | 峰值 16 处，出厂 **0** |
| JSON 构造 | 3 次语法错误、白跑三轮 | `JSON.stringify(对象数组)` → **3 → 0** |
| 校验/改动分离 | 串联"修补+装配" | 先 `--check` 再单独装配 → 返工 **2 → 0** |
| 判据来源 | `--check \| tail`：退出码来自 tail，**FAIL 被当成功继续装配** | 按输出内容判定 → **1 → 0** |
| 写入前自检 | 变量名不一致 → 整批作废 | 写入后立即 `JSON.parse` → **1 → 0** |
| 脚本复用 | 按目录名替换生成脚本 → 丢字段 → apply 抛错、8 篇白写 | 复用已验证脚本 / 从 catalog 反查补齐 → **8 → 0** |
| 判据唯一来源 | 手工摘抄闸门检字表 → 漂移（繁体表少 20 余字、评价表用简体，**一直在漏判**）| 直读闸门常量 → 漂移 **→ 0** |

**元规则**：把"需要人记住的东西"变成"**失败会立刻暴露的步骤**"；**修复的位置必须早于失效的位置**；**判据只能有一个来源、一个副本**；**能换成可数判据的，就不留在"感觉"层**。

### 起笔规则（叙述）

| 内容类型 | 高发栏位 |
|---|---|
| 现代国家 | 关键节点段（事件）|
| 古代王朝 | 经济段、文化段 |
| 现代非洲国家 | 关键节点段 |
| **薄素材**（事实数 2–3）| **结构目标：最薄弱一栏先写满两个完整分句再收尾** |

- **可数判定**：事实数 2–3 → 结构目标；4+ → 字数目标；**不确定按结构目标**（错判代价不对称：多写一个分句 vs 返工一轮）。
- **规则可叠加**：类型规则与薄素材规则同时成立时，**结构目标优先**。

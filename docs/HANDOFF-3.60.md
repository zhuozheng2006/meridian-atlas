# 经纬纪 3.60：更早显示底图与唐代名称核查

## 当前成果与本轮判断

3.59 已具备按年份读取的全球疆域、自动地区详图、原始记录下载、双语阅读和387个内容指纹数据包。当前主要短板仍是历史覆盖不均、概览来源线形粗糙、部分地名未审校，以及慢网下首屏等待较长。南亚三组学术图版仍是研究入口，尚未形成新增年度矢量边界。

本轮实际限速检查发现：渲染引擎已经下载完毕，地图却继续等待约603 KB的压缩目录，造成可以避免的空白等待。修复优先解决这段依赖等待，同时继续逐条审校唐代区划。

## 本轮改进

- 渲染引擎就绪后即可建立底图，与历史目录并行准备。主地图在目录与底图同时就绪后开启可选地理图层，再提交当前历史年份；区域详图仍沿用已有加载规则。
- 启动失败只清理该次创建的地图，取消后的迟到回调不会重新创建旧实例。销毁正在初始化的地图会结束就绪等待并清除超时计时器。
- 延后地理层时保持原有水系、区域边界和历史街区的叠放顺序；双图对照沿用原有默认初始化方式。
- 新核查23条742年名称：江南西道12、黔中道11。累计125/420条，其中汉62、唐63，尚余295条。按年份、PrefID、源名称和道名精确匹配，保留原始名称及下载记录。来源为《旧唐书》卷40；原文人口数字只作身份交叉核对。
- 洪州762年、鄂州833年、业州744年的县级变化未提前套用于742年。另有10个候选项因版本数字、道属日期或多音字待核，继续保留在台账。

## 验证

受控测量使用本机预览、同一浏览器、同一南亚视角（前250年），主页面禁用缓存，设置下载1.5 Mbps、上传0.75 Mbps、延迟150 ms。工作线程可能复用已有底图缓存，因此不能视为完全冷启动，也不代表线上所有网络和地区。

最终版本底图在约5.40秒就绪，而基线约9.42秒才开始创建；历史地图可交互时间分别为9.522秒与9.530秒，未测得这一指标的实质改善。中间方案的两次底图就绪时间为5.38、5.82秒。

测量原始值及最终版本结果见 `verification-3.60/browser/startup-measurements.json`。前后分别记录底图建立、底图就绪、历史地图交互就绪与目录传输完成，避免把提前显示底图等同于历史数据全部加载完成。中间方案的两次测量也保留。

启动回归执行实际应用函数与地图类，检查并行依赖、并发共享、失败重试、切换页面、迟到回调、销毁计时器、图层顺序及对照地图。完整套件、HTTP、打包、浏览器截图和线上文件核对证据保存在本批目录。首次完整测试发现旧视图还原测试替身未实现新增启动接口，导致10项失败；补齐测试替身后69项视图还原检查全部通过，原始失败日志保留。浏览器已验证742年自动显示50条区划及零陵郡名称考证，未记录控制台错误。最终发布信息见 `verification-3.60/publication.json`。

## 下一轮优先级

1. 历史目录仍是慢网下完整可用地图的主要瓶颈。研究按首屏所需字段拆分目录、随后载入完整研究字段；必须维持搜索、国家档案及原始记录的一致性。
2. 增加完全冷缓存、不同设备和线上网络的首屏与详图耗时检查。本轮仅证明依赖顺序修复和限定条件下的表现。
3. 继续295条汉唐名称审校，优先处理已有原文但存在版本数字、读音或年度归属疑点的记录。
4. 推进南亚单幅明确年代学术图版的配准与独立残差核验，然后再数字化边界。无详图地区要补来源几何；显示曲线无法提升史料本身的定位精度。

## 不变的资料范围

本轮没有新增边界坐标、重新估计人口或补造古代疆域。R2数据对象与版本未变，导入入口保持关闭。继续沿用现有站点访问范围；GitHub公开源码与站点访问设置分别管理。
